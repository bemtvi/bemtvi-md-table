Lines up the columns of markdown pipe tables on screen without changing the
text. Built entirely on the native `btv.*` plugin API.

A table typed without padding:

>markdown
    | Queue | Upstream | Applied by |
    |---|---|---|
    | ingest | kafka://events | worker-a |
<

is drawn as:

>markdown
    | Queue ·| Upstream ······| Applied by |
    |--------|----------------|------------|
    | ingest | kafka://events | worker-a ··|
<

The padding is inline virtual text, drawn dimmed so it can't be mistaken for
text you typed: the added spaces as `·`, the added dashes as `-` like the
separator itself. The buffer holds exactly what you typed, so writing the file
leaves it unchanged, and motions move over the real characters only. Both the
glyphs (see |bemtvi-md-table-fill-chars|) and the colours (see
|bemtvi-md-table-highlights|) can be changed.

==============================================================================
1. Install                                           *bemtvi-md-table-install*

Put the repo on your `runtimepath` with `btv.plugins` or any plugin manager.
`plugin/bemtvi-md-table.lua` auto-sources on load and turns alignment on with
the defaults, so there is nothing to configure:

>lua
    btv.plugins({
      { "bemtvi/bemtvi-md-table" },
    })
<

Run `:PluginSync` to clone it, then open a markdown file.

Tables are found by the markdown treesitter grammar. Without it nothing is
aligned: install it once with `:TSInstall markdown`.


==============================================================================
2. What it aligns                             *bemtvi-md-table-what-it-aligns*

A GFM pipe table, as the markdown treesitter grammar finds it: a header row, a
delimiter row with the same number of cells, then body rows, at the top level
or inside a list item or block quote. Each column is widened to its widest
cell, measured in display cells, so CJK text and emoji line up. A shorter cell
gets the difference as padding:

- spaces before its closing `|`, in a left-aligned (or unmarked) column;
- spaces before its text in a right-aligned column (`---:`), split on both sides in a centered
    one (`:---:`);
- on the delimiter row, dashes after the cell's last `-`, so alignment colons stay at the edges.

Rows with and without outer pipes line up with each other, since column 1 is
measured from the start of the line. A `\|` is a literal pipe, not a cell
boundary.

Left alone, because the grammar doesn't call them tables:

- tables inside a fenced code block (````` or `~~~`);
- tables indented four or more spaces (an indented code block);
- lines that hold a `|` but are not part of a table (no delimiter row under a header).

Buffers where treesitter is off (`btv.bo.ts_highlight = false`) get no
alignment either.

The last cell of a row with no trailing pipe counts toward its column's width
but is not padded, because nothing after it needs lining up.

3. Toggles                                           *bemtvi-md-table-toggles*

>lua
    btv.g.md_table_align = false          -- off everywhere (default: on)
    btv.b.md_table_align = false          -- off in the current buffer
    btv.b[bufnr].md_table_align = false   -- ...or a specific buffer
<

A buffer's explicit value wins over the global one. Both are read on every
repaint; after changing one from Lua, call
`require("bemtvi-md-table").refresh()` to repaint straight away.


:MDTABLETOGGLE                        *bemtvi-md-table-toggles-:mdtabletoggle*

`:MdTableToggle` flips alignment for the current buffer and repaints it.

4. Rewriting a table                       *bemtvi-md-table-rewriting-a-table*

The alignment above is only drawn. Two commands change the text itself, for
when the file should hold a grid (or should stop holding one).


:MDTABLEEXPAND              *bemtvi-md-table-rewriting-a-table-:mdtableexpand*

`:[range]MdTableExpand` writes the table under the cursor as the aligned grid
the plugin draws, with real spaces and dashes:

>markdown
    | Queue  | Upstream       | Applied by |
    |--------|----------------|------------|
    | ingest | kafka://events | worker-a   |
<

Stray spacing in the cells is dropped first, then each cell is padded to its
column's widest, before its text in a right-aligned column and on both sides
in a centered one (with `align = false` in `setup`, always on the right). Once
the text is a grid there is nothing left to pad, so no padding is drawn over
it.


:MDTABLESHRINK              *bemtvi-md-table-rewriting-a-table-:mdtableshrink*

`:[range]MdTableShrink` writes the table in the least space it takes: each
cell's text one space from its pipes (an empty cell is a single space), and
each delimiter cell cut to three characters that keep its alignment, `---`,
`:--`, `--:` or `:-:`, with no spaces around them:

>markdown
    | Queue | Upstream | Applied by |
    |---|---|---|
    | ingest | kafka://events | worker-a |
<

Alignment, if on, keeps drawing the shrunk table as a grid.

Both commands:

- rewrite every table the range touches when given one (`:%MdTableExpand` does the whole buffer);
- keep each row's outer pipes, or their absence, and never add or drop a cell;
- keep what comes before the table on each row: a block quote's `>` and a list item's indent;
- find tables through the markdown treesitter grammar, as the alignment does, so a table in a code
    fence is never touched;
- fail with an error, leaving the buffer alone, when there is no table at the cursor or in the
    range;
- leave an already-formatted table untouched (the buffer isn't marked modified) and say so.

5. Configuration                               *bemtvi-md-table-configuration*

`require("bemtvi-md-table").setup(opts)` reconfigures.
`plugin/bemtvi-md-table.lua` calls it with `{}` for you; calling it again from
a config re-applies. Unknown keys are an error.

>lua
    require("bemtvi-md-table").setup({
      filetypes = { "markdown" },  -- the filetypes whose tables are aligned
      align = true,                -- honor ---: and :---: in the cells; false pads
                                   -- every cell on the right
      fillchars = "pad:·,delimiter:-",  -- the glyphs the padding is drawn in
    })
<


==============================================================================
6. Fill chars                                     *bemtvi-md-table-fill-chars*

The glyphs the padding is drawn in, set like the core's `'fillchars'` and
`'listchars'`: a comma-separated `key:char` list.

>lua
    require("bemtvi-md-table").setup({ fillchars = "pad:·,delimiter:-" })
<

- `pad` — drawn in place of the spaces added to the cells. Default `·`.
- `delimiter` — drawn in place of the dashes added to the delimiter row. Default `-`.

The char is the one character after the colon, so `,` and `:` work as fill
chars too (`"pad:,"`). Each must be one display cell wide. A key left out keeps
its default, so `"pad: "` changes only the spaces. The table form `btv.opt`
gives map options works too: `{ pad = " " }`. `"pad: "` draws the padding as
plain spaces, its colour aside.

Like a global-local option, it can be set at three levels, the most specific
winning:

>lua
    require("bemtvi-md-table").setup({ fillchars = "pad: " })  -- the base
    btv.g.md_table_fillchars = "pad:."                          -- overrides setup
    btv.b[bufnr].md_table_fillchars = { pad = "+" }             -- one buffer
<

The variables are read on every repaint; after changing one from Lua, call
`require("bemtvi-md-table").refresh()` to repaint straight away. An invalid
value is an error: `setup` raises it, and a variable is reported once on the
message line as `E474`, with that buffer's tables left unaligned until it is
fixed.


==============================================================================
7. Highlights                                     *bemtvi-md-table-highlights*

- `MdTableDelimiter` — the dashes added to the delimiter row. Linked by default to `NonText`.
- `MdTablePad` — the spaces added to the cells. Linked by default to `NonText`.

`NonText` is the dim group for glyphs that aren't part of the text, which
keeps the padding visibly apart from what you typed.

Both are `default` links, so a colorscheme or your config can restyle them.
They are re-linked after a colorscheme loads.

8. API                                                   *bemtvi-md-table-api*


SETUP                                              *bemtvi-md-table-api-setup*

`require("bemtvi-md-table").setup(opts)`

See |bemtvi-md-table-configuration|.


ENABLED                                          *bemtvi-md-table-api-enabled*

`require("bemtvi-md-table").enabled(bufnr)`

Whether tables are aligned in `bufnr` (`0` = the current buffer), from the
toggles above.


TOGGLE                                            *bemtvi-md-table-api-toggle*

`require("bemtvi-md-table").toggle(bufnr)`

Flip alignment for `bufnr` (default: the current buffer), repaint it, and
return the new state.


REFRESH                                          *bemtvi-md-table-api-refresh*

`require("bemtvi-md-table").refresh(bufnr)`

Repaint `bufnr`'s windows now, or every visible window with no argument.


SHRINK                                            *bemtvi-md-table-api-shrink*

`require("bemtvi-md-table").shrink(bufnr, first, last)`

What `:MdTableShrink` runs. Rewrites every table touching the 0-based rows
`first` to `last` (inclusive) of `bufnr` (default: the current buffer, at the
cursor). Returns a promise of the number of tables whose text changed; it
rejects when there is no table there.


EXPAND                                            *bemtvi-md-table-api-expand*

`require("bemtvi-md-table").expand(bufnr, first, last)`

What `:MdTableExpand` runs, with the same arguments and result as
|bemtvi-md-table-shrink|.


FILLCHARS                                      *bemtvi-md-table-api-fillchars*

`require("bemtvi-md-table").fillchars(bufnr)`

The fill chars in effect for `bufnr` (`0` = the current buffer), as `{ pad =
..., delimiter = ... }`: the buffer's variable, else the global one, else
setup's. An invalid variable returns `nil` and the `E474` message. See
|bemtvi-md-table-fill-chars|.

9. How it works                                 *bemtvi-md-table-how-it-works*

A `btv.decor.provider` scoped to the configured filetypes runs whenever a
window's viewport changes: on scroll, resize, or an edit. It declares the
treesitter query `(pipe_table) @table`, so each run is handed the tables that
touch the viewport, each with its full extent even where it runs above or below
the screen. It reads each table's rows, so the columns agree past the edge,
and publishes one inline `virt_text` mark per padded cell. Each publish
replaces the previous one, so nothing is left behind when a cell shrinks. While
the grammar is still loading, or a large file's first parse is unfinished, it
keeps what is drawn and runs again when the tree is ready.

The work is bounded by what is visible. Only tables on screen are measured, and
each table's layout is cached until the buffer next changes (keyed on
`btv.buf.changedtick`).

10. Tests                                              *bemtvi-md-table-tests*

>sh
    bemtvi --test-plugin .
<

The suite runs in a real headless editor. It opens markdown files and checks
the painted rows, with the inline padding put back in, and also drives the
runnable example in `examples/`. The tests that draw tables need the markdown
grammar and are reported as skipped without it.
